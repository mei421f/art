# Artosphere Branding

سایت تبلیغاتی/پورتفولیوی دو زبانه (فارسی/انگلیسی) برای استودیوی برندینگ Artosphere —
کوروش آرزومند. بک‌اند Node.js/Express، فرانت‌اند HTML/CSS/JS خالص (بدون فریمورک)،
و دیتابیس Postgres روی **Neon.tech** (رایگان). آماده برای دیپلوی روی **Railway**.

## ساختار پروژه

```
artosphere/
├── backend/
│   ├── server.js          سرور اصلی Express
│   ├── db/
│   │   ├── pool.js        اتصال به Postgres (Neon)
│   │   ├── schema.sql     تعریف جدول‌ها (projects / messages / admins / media)
│   │   ├── migrate.js     اجرای خودکار schema در هر استارت
│   │   └── seed.js        ساخت پروژه‌های نمونه (ROVA/KOVA) و کاربر ادمین
│   ├── routes/
│   │   ├── auth.js        ورود ادمین (JWT) + وضعیت اتصال تلگرام
│   │   ├── projects.js    API عمومی + مدیریت پروژه‌ها
│   │   ├── contact.js     فرم تماس + مدیریت پیام‌ها + ارسال به تلگرام
│   │   └── uploads.js     آپلود عکس/ویدیو (multer) + کتابخانه رسانه
│   └── middleware/adminAuth.js
├── public/
│   ├── index.html          صفحه اصلی (Home → Work → Services → About → Process → Contact)
│   ├── admin.html          پنل مدیریت (بازطراحی‌شده، ریسپانسیو)
│   ├── uploads/             فایل‌های آپلودشده از پنل (در دیپلوی ساخته می‌شود)
│   └── assets/
│       ├── admin.css       استایل پنل مدیریت
│       ├── admin.js        منطق پنل مدیریت
│       └── ...              CSS سایت، JS سایت، فونت، تصاویر placeholder
├── railway.json
└── .env.example
```

## پنل مدیریت — چه چیزی تغییر کرد

- **آپلود واقعی عکس/ویدیو:** در فرم هر پروژه، دکمه «انتخاب فایل از دستگاه» فایل‌منیجر
  گوشی/کامپیوتر ادمین را باز می‌کند؛ فایل مستقیماً به سرور آپلود و مسیرش در دیتابیس
  ذخیره می‌شود (جدول `media` + فیلد `cover_image`/`cover_type` روی هر پروژه). یک تب
  «رسانه‌ها» هم اضافه شده که همه فایل‌های آپلودشده را نشان می‌دهد و دکمه «انتخاب از
  رسانه‌های قبلی» در فرم پروژه، همان‌ها را برای استفاده مجدد نشان می‌دهد.
- **ریسپانسیو:** پنل از نو با چیدمان کارتی (به‌جای جدول‌های سخت) و ناوبری‌ای که در
  موبایل به نوار پایین صفحه تبدیل می‌شود، بازطراحی شده.
- **اتصال به تلگرام:** پیام‌های فرم تماس سایت، علاوه بر ذخیره در دیتابیس، به یک ربات
  تلگرام هم ارسال می‌شوند (اختیاری، با تنظیم دو متغیر محیطی — پایین‌تر توضیح داده شده).

### راه‌اندازی ربات تلگرام

1. در تلگرام به [@BotFather](https://t.me/BotFather) پیام دهید و با دستور `/newbot`
   یک ربات بسازید؛ توکنی شبیه `123456:ABC-DEF...` می‌گیرید.
2. برای پیدا کردن «چت‌آیدی» مقصد (چت خودتان یا یک گروه)، به ربات
   [@userinfobot](https://t.me/userinfobot) پیام دهید (یا ربات را به گروه اضافه کنید
   و آیدی گروه را از [@RawDataBot](https://t.me/RawDataBot) بگیرید).
3. در متغیرهای محیطی سرور (Railway → Variables یا فایل `.env` محلی) این دو مقدار را
   اضافه کنید:

   | متغیر | مقدار |
   |---|---|
   | `TELEGRAM_BOT_TOKEN` | توکن ربات از BotFather |
   | `TELEGRAM_CHAT_ID` | آیدی عددی چت/گروه مقصد |

   اگر این دو مقدار خالی بمانند، سایت و پنل عادی کار می‌کنند و فقط ارسال به تلگرام
   غیرفعال است (وضعیتش در تب «پیام‌ها»ی پنل نمایش داده می‌شود).

### نکته مهم درباره آپلود فایل روی Railway

فایل‌های آپلودشده از پنل روی دیسک سرویس (`public/uploads`) ذخیره می‌شوند. روی
Railway، دیسک سرویس‌های معمولی **پایدار (persistent) نیست**؛ یعنی با هر ری‌دیپلوی یا
ری‌استارت ممکن است فایل‌های قبلی پاک شوند. برای جلوگیری از این مشکل، از بخش
**Volumes** در تنظیمات سرویس Railway یک Volume بسازید و آن را روی مسیر
`/app/public/uploads` مونت کنید تا فایل‌های آپلودی همیشه باقی بمانند.

## ۱) ساخت دیتابیس رایگان روی Neon

1. به [neon.tech](https://neon.tech) بروید و یک حساب رایگان بسازید.
2. یک پروژه جدید بسازید (مثلاً با نام `artosphere`).
3. از داشبورد پروژه، بخش **Connection string** را باز کنید و مقدار کامل آن را کپی کنید؛
   چیزی شبیه این:
   ```
   postgresql://user:password@ep-xxxx-xxxx.aws.neon.tech/neondb?sslmode=require
   ```
4. این مقدار همان `DATABASE_URL` است — نیازی به ساخت دستی جدول نیست؛ سرور در هر
   بار اجرا خودش جدول‌های لازم را می‌سازد (`db/migrate.js`) و پروژه‌های نمونه و
   کاربر ادمین را در صورت نبود می‌سازد (`db/seed.js`).

## ۲) دیپلوی روی Railway

1. یک پروژه جدید در [railway.app](https://railway.app) بسازید و این ریپازیتوری را
   وصل کنید (یا فایل‌ها را مستقیم آپلود کنید).
2. Railway به‌صورت خودکار `railway.json` را می‌خواند: نصب با Nixpacks و اجرا با
   `npm start`.
3. در بخش **Variables** پروژه روی Railway، این متغیرها را اضافه کنید:

   | متغیر | مقدار |
   |---|---|
   | `DATABASE_URL` | Connection string کپی‌شده از Neon |
   | `JWT_SECRET` | یک رشته تصادفی و طولانی (برای امنیت توکن ادمین) |
   | `ADMIN_USERNAME` | نام کاربری دلخواه برای ورود به `/admin` |
   | `ADMIN_PASSWORD` | رمز عبور قوی برای ورود به `/admin` |

   (نمونه کامل در `.env.example`)

4. دیپلوی کنید. بعد از بالا آمدن سرویس:
   - سایت اصلی: آدرس Railway شما (یا دامنه سفارشی)
   - پنل مدیریت: همان آدرس + `/admin`

5. برای وصل‌کردن دامنه `artospherebranding.ir`: در تنظیمات Railway بخش
   **Networking → Custom Domain** دامنه را اضافه کنید و رکوردهای CNAME/A پیشنهادی
   Railway را در تنظیمات DNS دامنه (مثلاً نیک یا هر ثبت‌کننده دیگر) وارد کنید.

## ۳) اجرای محلی (اختیاری)

```bash
cp .env.example backend/.env   # و مقادیر را پر کنید
npm install
npm start
```

سرور روی `http://localhost:5000` بالا می‌آید.

## نکات فنی

- **دو زبانگی:** هر متن دارای دو نسخه `data-fa` و `data-en` است؛ سوییچ زبان در
  هدر، `dir` صفحه را بین `rtl`/`ltr` عوض می‌کند و انتخاب کاربر در `localStorage`
  ذخیره می‌شود — دو زبان هرگز همزمان نمایش داده نمی‌شوند.
- **پروژه‌ها از دیتابیس می‌آیند:** بخش «کارها» به‌صورت پویا از `/api/projects`
  خوانده می‌شود؛ افزودن/ویرایش/حذف پروژه از پنل `/admin` انجام می‌شود — نیازی به
  تغییر کد نیست.
- **فرم تماس:** پیام‌ها در جدول `messages` ذخیره می‌شوند و در تب «پیام‌ها»ی پنل
  مدیریت قابل مشاهده‌اند.
- **طراحی بصری:** این نسخه یک پایه‌ی حرفه‌ای minimal/editorial با تایپوگرافی
  بزرگ، فضای خالی زیاد و انیمیشن‌های ظریف اسکرول است. رنگ‌ها، فونت نهایی، لوگو
  و تصاویر از طریق متغیرهای CSS در ابتدای `public/assets/style.css` و فایل‌های
  `public/assets/fonts` / `public/assets/images` به‌راحتی قابل جایگزینی‌اند.
- **ریسپانسیو:** چیدمان از موبایل تا دسکتاپ تست‌شده (منوی همبرگری در موبایل،
  گرید ستون‌ها در تبلت/دسکتاپ).
